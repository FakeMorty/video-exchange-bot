# Автоматизация DonationAlerts

## Что автоматизировано

Бот больше не привязывает платёж к Telegram ID, введённому в произвольное поле. Перед оплатой пользователь выбирает пакет, а бот создаёт одноразовый код вида `DA-XXXXXXXXXX`. Пользователь вставляет этот код в поле «Сообщение» DonationAlerts и указывает точную сумму. Награда выдаётся только при одновременном совпадении кода, суммы и статуса ожидающего заказа.

| Сценарий | Результат |
|---|---|
| Код и сумма совпали с действующим заказом | Монеты или VIP начисляются автоматически; код становится завершённым. |
| Код отсутствует, неизвестен или просрочен | Донат не зачисляется автоматически и создаётся запись в админ-очереди. |
| Сумма не совпала с выбранным пакетом | Донат не зачисляется автоматически и создаётся запись в админ-очереди. |
| Одно событие пришло повторно | Повтор не меняет баланс: `Payment.payload` уникален по ID доната. |
| Real-time соединение временно недоступно | Раз в 60 секунд работает REST-сверка последних платежей. |

## Настройка OAuth

1. Войдите в DonationAlerts и создайте OAuth-приложение в разделе [`/application/clients`](https://www.donationalerts.com/application/clients).
2. Для redirect URI укажите `https://video-exchange-bot.onrender.com/donationalerts/oauth/callback` или соответствующий URL вашего публичного сервиса. Это значение должно совпасть с `DONATION_ALERTS_OAUTH_REDIRECT_URI` в Render.
3. В Render → **Environment** добавьте `DONATION_ALERTS_CLIENT_ID`, `DONATION_ALERTS_CLIENT_SECRET`, `DONATION_ALERTS_OAUTH_REDIRECT_URI`, случайный `DONATION_ALERTS_OAUTH_STATE` и `DONATION_ALERTS_URL`. Не добавляйте эти значения в Git.
4. Сделайте короткий деплой, затем откройте `https://video-exchange-bot.onrender.com/donationalerts/oauth/start`. Войдите в DonationAlerts и подтвердите только необходимые scope: `oauth-user-show`, `oauth-donation-index`, `oauth-donation-subscribe`.
5. После callback сервис один раз покажет `refresh_token`. Скопируйте его в Render → **Environment** как `DONATION_ALERTS_REFRESH_TOKEN`, закройте страницу и перезапустите сервис. Не публикуйте токен в чате, репозитории или скриншотах.
6. Оставьте `DONATION_ALERTS_ACCESS_TOKEN` пустым, если используется refresh token. Эта переменная предусмотрена только как ограниченный резерв для уже выданного OAuth access token.
7. После второго запуска проверьте в «Админка → Управление DonationAlerts» статус `OAuth-синхронизация включена`.

> Не используйте старый публичный URL webhook для начисления. Он сохранён только как совместимый ответ `410`, потому что открытый JSON без криптографической проверки нельзя считать доказательством оплаты.

## Очередь сверки

Откройте **Админка → Управление DonationAlerts → Очередь сверки**. Каждая карточка содержит ID доната, сумму, причину, текст сообщения и возможного пользователя. Перед ручным зачислением обязательно сравните ID и сумму с кабинетом DonationAlerts. Закрытие карточки без начисления не меняет баланс пользователя.

## Проверка после запуска

Создайте тестовый заказ на минимальный пакет и выполните только тестовый или реальный платёж, который вы готовы принять. Убедитесь, что сумма точная, а код заказа полностью вставлен в сообщение. Бот должен прислать уведомление о зачислении, а в админ-очереди не должно появиться исключение.
